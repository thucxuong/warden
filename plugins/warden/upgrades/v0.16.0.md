Finished runs are no longer committed to `.warden/history/`. Without a database, warden keeps them in `.warden/state/_records/` on the machine that ran them, which git ignores. A team that wants one place for its runs points warden at a database. Do these steps in order, in the main checkout, on the main branch.

1. Run `warden status --all`. If any run is `active`, `waiting` or `blocked`, stop here and tell the user to finish or archive it first, then run `/warden:upgrade` again.
2. Ask the user whether the team wants one place for all its runs, live and finished, in a database. If not, skip this step: everything stays in `.warden/state/` on each machine. If yes: warden connects by itself through `WARDEN_DB_URL`, set in each person's shell or in the project's git-ignored `.env`, never committed. It takes `sqlite:<path>` or `postgres://...`. A SQLite file must be outside the repo: suggest `sqlite:~/.warden/<project>.db`. Ask which env vars hold secrets that could show up in a log, and add their names to `.warden/warden.json` as `"secrets": [...]`. The database is set up by step 3 of `/warden:upgrade` (`warden db migrate`).
3. Run `warden records import`. It saves the runs in `.warden/history/` (when that folder exists) and every finished run in `.warden/state/` that has no record yet. It prints `{ imported, failed }`. If `failed` is not empty, stop and show it to the user: do not go on to step 4.
4. Run `git rm -r .warden/history` if that folder is tracked. Old copies stay in git history.
5. If `.warden/tools/roles.json` has a `records` role from an early 0.16.0 build, remove that line and the tool it names: warden no longer uses it.
6. Tell the user that shipped tickets no longer add a `run record` commit, and where runs are now kept. Without a database, each machine sees only its own. With one, every machine that runs warden needs `WARDEN_DB_URL`, and `warden start` refuses a ticket another machine is running (its owner hands it over with `warden handoff <ticket>`, and the next `warden start <ticket>` continues it; when that machine is gone, a person runs `warden db release <ticket>`).
