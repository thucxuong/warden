Finished runs are no longer committed to `.warden/history/`. Without a database, warden keeps them in `.warden/state/_records/` on the machine that ran them, which git ignores. A team that wants to share them sets up a database. Do these steps in order, in the main checkout, on the main branch.

1. Run `warden status --all`. If any run is `active`, `waiting` or `blocked`, stop here and tell the user to finish or archive it first, then run `/warden:upgrade` again.
2. Ask the user whether the team wants to share finished runs in a database, or keep them on each machine. If they want a database, ask which one, and which environment variable holds its login. Prefer one the project already runs. Write the tool as `recipes/records.md` in the warden:tools skill says, create its table, set `"records": "<tool>"` in `.warden/tools/roles.json`, and run `warden tools --verify records` until it exits 0. If the database is not ready, go on without it: it can be added later with `/warden:tools records`.
3. If `.warden/history/` exists, run `warden records import`. It prints `{ imported, failed }`. If `failed` is not empty, stop and show it to the user: do not go on to step 4.
4. Run `git rm -r .warden/history` if that folder is tracked. Old copies stay in git history.
5. Run `warden tools --skill` and `warden tools --check`: it must exit 0.
6. Tell the user that shipped tickets no longer add a `run record` commit, and where finished runs are now kept. Without a database, each machine sees only its own. With one, every machine that runs warden needs its environment variable.
