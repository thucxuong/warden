Project knowledge moves from `.warden/` to `docs/`, and decisions are grouped by area. Do these steps in order, in the main checkout, on the main branch. `/warden:docs` has the layout this ends in.

1. Run `warden status --all`. If any run is `active`, `waiting` or `blocked`, stop here and tell the user to finish or archive it first, then run `/warden:upgrade` again. A live run's worktree still has the old layout.
2. Run `git mv .warden/knowledge docs/knowledge` and `git mv .warden/retros docs/retros`. Create `docs/` first if the project has none. Leave the files as they are. Old links inside retros stay as a record of the past.
3. Move each decision file in `.warden/decisions/` with `git mv`, except `INDEX.md`:
   - Pick its area from what it is about: a short lowercase folder name such as `be`, `fe`, `devops` or `architect`. Use as few areas as fit the project.
   - Its date is the `Date:` line in the file. Without one, use the date it was first added: the last line that `git log --format=%as -- <file>` prints.
   - The new path is `docs/decisions/<area>/<YYYY-MM-DD>-<slug>.md`, where `<slug>` is the old name without its `NNNN-`.
   - If its status says it was replaced or is no longer in force, the path goes under `docs/archived/` instead: `docs/archived/decisions/<area>/<YYYY-MM-DD>-<slug>.md`.
   - Do not change what the file says. Its old number stays in its title, so a mention such as "decision 0035" can still be found by searching.
4. Write `docs/decisions/INDEX.md` from the old `.warden/decisions/INDEX.md`: one `## <area>` heading per area, under it the line of each decision in that area, with the new path from `docs/decisions/` as its target. Leave archived decisions out. Then `git rm .warden/decisions/INDEX.md`.
5. For each file in `.warden/context/` other than `INDEX.md`:
   - If a doc in `docs/` covers the same topic, copy over only the facts that doc lacks. The doc in `docs/` wins when they disagree. Then `git rm` the file.
   - If none does, `git mv` it to `docs/<name>.md`.
   Then `git rm .warden/context/INDEX.md`. No `.warden/context/` is left.
6. Write `docs/INDEX.md`, unless it exists: `# Docs`, then a line `- <path>: <what it covers>` for each `.md` file directly in `docs/`, one line for each other folder in `docs/` (its `INDEX.md` or `README.md`, else its first file), and leave out `docs/archived/`. Lines for `knowledge/INDEX.md`, `decisions/INDEX.md` and `retros/INDEX.md` are part of this.
7. In `.warden/checks/retro.md`, replace `.warden/retros/<YYYY-MM-DD>.md` with `docs/retros/<YYYY-MM-DD>.md`.
8. In `.warden/checks/warden-docs.md`, replace the paragraph under the heading with: `docs/INDEX.md lists every top-level doc and every other folder in docs/. Every .md file in docs/knowledge, docs/decisions, docs/retros, .warden/rules and .warden/checks has a line in its folder's INDEX.md, every INDEX.md line names a file that exists, and none of those files is over 200 lines. Decisions and retros have dated names, and an archived file has left its old place and is in no index. When it fails, run warden docs check and fix what it lists; the warden:docs skill says how.`
9. In `.warden/steps.json`, remove `.warden/knowledge/**` from `fix.scope`, and add `docs/**` if it is not there.
10. Search the project's own files for `.warden/knowledge`, `.warden/decisions`, `.warden/context` and `.warden/retros`: `.warden/rules/`, `.warden/flows/`, `.warden/tools/`, `steps.json`, `AGENTS.md`, `CLAUDE.md`, scripts, and docs outside `docs/retros/` and `docs/archived/`. Point each one at the new place. Leave `.warden/history/` and `.warden/fixes/` alone: they are records of the past.
11. Run `warden docs check` and fix what it lists, until it passes.
12. Run each command in `check` in `.warden/steps.json`. The moved notes are now in `docs/`, so a formatter, a linter or a docs script that skipped `.warden/` may now fail on them. If one fails because of the move, change the project's config, for example add `docs/knowledge/`, `docs/decisions/`, `docs/retros/`, `docs/archived/` and `docs/INDEX.md` to its ignore list. Do not reformat the notes.
13. If the project publishes `docs/` as a site, tell the user: `docs/knowledge/`, `docs/decisions/`, `docs/retros/`, `docs/archived/` and `docs/INDEX.md` get published unless the site leaves them out. A home page named `docs/index.md` is the same file as `docs/INDEX.md` on macOS and Windows.

Add the moved paths to the commit in the last step of `/warden:upgrade`.
