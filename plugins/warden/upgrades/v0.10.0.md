The retro counts what the agent ran (from Claude Code's session transcripts) to suggest new tools, a project tools skill tells the agent which tools exist, and `warden tools --verify tickets` checks the ticket tool.

1. Run `warden tools --init`. It writes `.warden/tools/replaces.json` as `{}` and keeps every file that exists.
2. In `.warden/tools/tool.ts`, if the `Tool` interface has no `commands` line, add it after the `probe` line, exactly: `  commands?: string[];                            // first-level commands, listed in the project tools skill`
3. Run `warden tools --skill`. It writes `.claude/skills/project-tools/SKILL.md`, the list of this project's tools for the agent.
4. Run `warden tools --verify tickets`. It tests the ticket tool in a throwaway copy and changes nothing. If a row is `FAIL`, tell the user what it says; fix the tool only when the user agrees.

To list the raw commands a tool covers, so the skill and the retro can steer the agent to the tool, see `/warden:tools` (section "Raw commands a tool covers").
