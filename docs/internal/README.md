# Internal design notes

Design and build specs used to build warden. They are not user docs and may be out of date: the code wins. User docs start at [../README.md](../README.md).

- [design.html](design.html): the original design page (architecture, terms, behaviour).
- [spec.md](spec.md): build spec for 0.1, the base the later specs build on.
- [spec-0.2.md](spec-0.2.md): build spec for 0.2 additions (report status, periodic checks, newer-version notice, maintainer doorbell).
- [spec-0.3.md](spec-0.3.md): build spec for 0.3 additions (ticket tools, the `chore` template, orchestration of epics, several live runs).
- [spec-0.4.md](spec-0.4.md): build spec for 0.4 additions (reports from other machines, the `warden-docs` check).
- [spec-0.5.md](spec-0.5.md): build spec for 0.5 (report conversations between maintainers and projects).
- [spec-0.6.md](spec-0.6.md): build spec for 0.6 (project-owned tools in `.warden/tools/`).
- [playground-requirements.md](playground-requirements.md): the menu of features, defects and scenarios for the playground app used to verify releases.
- [future-work.md](future-work.md): ideas kept for later, none planned.
